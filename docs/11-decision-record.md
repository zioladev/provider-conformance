# 11 — Decision record

The decisions that produced this spec, recorded like Phase I's D1–D10 so the reasoning survives
the conversation that created it. Each is ratified (author + GPT review).

| # | Decision | Rationale |
|---|---|---|
| **D1** | **Phase II is an evidence-and-attribution system, not an adapter package.** The report schema (§06) + attribution taxonomy (§05) are the spine; adapters/lanes are populators. | Centering on adapters risks "three clever vendor integrations" that never defined what conformance means. The durable asset is the measurement language. |
| **D2** | **Model-agnostic core; pluggable `ModelConsumerAdapter`s.** Generalize the existing `ModelAdapter`; browser-native agent is a *future* adapter, not the centre. | Only a normalize-once/route-through-adapters shape lets the *same* surface be compared across GPT/Claude/Gemini. |
| **D3** | **Same-surface invariant + one adapter-independent execution bridge.** Adapters decide *what* to call; the bridge executes against the *same* surface for all. | Without it, a difference could be model, translation, consumer logic, or plumbing — attribution becomes impossible. |
| **D4** | **N consumers from day one; Phase II is not complete until GPT+Claude+Gemini run one surface and divergence reporting works.** | The distinguishing feature (cross-consumer divergence) must actually arrive, not be deferred into a "conformance" package that only ever tested one path. |
| **D5** | **Versioned machine-readable report + human rendering, treated as a public contract** and the seed of Phase IV qualification. | A stable atom lets Phase IV aggregate rather than redefine. |
| **D6** | **Split-lane v0.1:** automated reference-runtime lane + real Chrome/WebMCP acceptance lane, clearly labeled; shim results never presented as browser conformance. | WebMCP is flag-gated Chrome-only today; honesty about what a shim proves is non-negotiable. Full real matrix is Phase VI. |
| **D7** | **`@zioladev/provider-conformance`, standalone public Apache-2.0.** Local/single-machine open; hosted recurring/browser/model matrix later. | Keeps core function genuinely open; puts the commercial center where the recurring cost is. |
| **D8** | **Mandatory attribution across nine categories; a consumer-side failure is never provider nonconformance.** Provider grade computed only from the four provider-owned categories. | Fault isolation is what makes "conformance" a serious word and the report actionable. |
| **D9** | **Divergence has a precise predicate** — same provider def + same task → materially different *observable* outcome — and is **descriptive, not automatically failure** (behavioral / outcome / conformance). | Prevents the harness from degrading into a model-consistency checker; *different ≠ wrong*. |
| **D10** | **Conformance ≠ interoperability.** Provider conformance is a prerequisite for interoperability, not interoperability itself; no journey/itinerary state in this package. | Stops Phase III from leaking backward into Phase II. |
| **D11** | **Observed facts vs. derived judgments are stored separately.** Verdicts are re-computable from raw observations; a re-score never re-runs. | Interpretation rules will change; the evidence must outlive any one interpretation. |
| **D12** | **Stable provenance identifiers** (`caseId`, `taskId`, `providerDefHash`, `toolSurfaceHash`, `adapterId`/`adapterVersion`, `modelId`, `runtimeId`, `browserVersion`, `modelParams`). | So "same test case, different model/runtime" is a fact, not a philosophical aspiration. |
| **D13** | **First-class outcome vocabulary; no collapsing into `not_executed`.** `executed`, `blocked_by_provider_contract`, `clarification`, `no_tool_selected`, `malformed_arguments`, `adapter_error`, `runtime_error`, `transport_error`, `execution_bridge_error`, `provider_error`. | "No provider call" means at least seven different things; collapsing them makes the report useless. |
| **D14** | **Frozen fixture discipline.** Task, provider def, tool surface, provider state, declared allowable outcomes, model params, runtime are pinned + hashed before a case runs. | If "same task" isn't actually the same, every verdict and divergence claim is unfounded. |
| **D15** | **Model narration excluded from core conformance scoring.** Captured as optional evidence only. | Keeps the judge-dependent language layer permanently out of the scoring path. |
| **D16** | **Clean-room extraction — total independence.** No runtime dep, dev dep, type-only import, generated artifact, fixture, or source path from `@selvage/*` (or the Refraktor extension) may be required to build, test, or execute the package. A CI check asserts the absence of any `@selvage` import/path. Selvage governance stays out entirely (Phase V, optional module on top). | Keeps proprietary governance logic from leaking into open tooling; the package must stand alone so the architecture tells the truth — conformance is not a thin public wrapper around proprietary enforcement. |
| **D17** | **`plan()` never executes — an architectural invariant, not an interface preference.** Adapters decide; the one common bridge executes. The type is renamed `ModelConsumerAdapter` (past the `@selvage/core` `ConsumerAdapter` collision). | If any adapter could execute, vendor paths would hide different execution behavior and the attribution taxonomy would collapse into "something went weird over there." |
| **D18** | **Golden report fixtures with authored, known-correct attribution**, locked in 2A, gating CI. Cover every provider-owned category + a divergence-≠-failure case. | Every future change to the report engine must preserve the attribution truths; without them Phase II becomes philosophically unstable as adapters accumulate. |
| **D19** | **Report identity includes the report generator** (`reportGenerator` / `reportGeneratorVersion`), and field names are deliberately literal, never cute. | A grade is only meaningful paired with the engine that computed it; the report is a durable contract Phase IV/VI build on — a clever name today is a migration tomorrow. |

| **D20** | **Task conformance is enforced against a frozen allowable set.** A clean terminal response outside the case's a-priori allowable set is a **consumer-side** fault (fabricated execution → `model_arguments`; illegitimate clarify/no-action → `model_tool_selection`), never provider-owned. "Execute with a default" is legitimate **only if the provider declares one.** Reuses existing categories → no report-version bump. | Without it, an underspecified task's fabrication is silently PASS. The rubric is frozen *before* models run; model behavior is observation, not ground truth. |
| **D21** | **The proof stack keeps its lanes separate.** A real model network path validated through the pipeline is a `reference-runtime/1` proof — **not** a real Chrome/WebMCP proof. The Chrome/WebMCP lane stays a distinct, later proof (2C). | Conflating "a real model ran" with "it ran against real WebMCP in Chrome" would overclaim. The clean stack: 2A instrument validation · 2B(det) adapter semantics · 2B(live) real model path on the reference lane · ambiguous-task divergence · 2C three-way + real Chrome lane. |

| **D22** | **Divergence is scored at two levels: representational vs. behavioral.** Observed outcomes (`clarification`, `no_tool_selected`, `executed`, …) stay distinct; a higher-order **action disposition** (`acted` / `deferred` / `failed`) drives behavioral divergence. Two paths that both `deferred` are not behaviorally divergent even when their labels differ. Text-only model output is **never** upgraded to `clarification` without a separate judge layer. | A live run showed a scripted `clarification` vs. a real model's `no_tool_selected` — same practical result, different label. The disposition layer keeps the raw outcome precise while preventing the divergence logic from inventing significance where there is none. `different ≠ wrong`; here, different isn't even behaviorally different. |

| **D23** | **`inspected` is a distinct disposition; attribution is effect-aware and first-failing-layer.** A read-only execution → `inspected` (not `acted`); state-changing → `acted`; no execution → `deferred`; failure → `failed`. An out-of-allowable execution attributes by where the first mismatch enters: a read / non-execution outside allowable → `model_tool_selection` ("selected an exploratory read outside allowable terminal outcomes"); a state-changing execution whose supplied required value violates the frozen task → `model_arguments`. No "fabricated input" wording where nothing was fabricated. The frozen rubric is **not** relaxed to bless the read. | A live run had Claude defer (ask the user) and GPT inspect (run `find_item`) on the same task — a real cross-ecosystem strategy difference the report must preserve without exaggerating it into a failure or blaming the provider. Whether a read is valid *trajectory* progress is Phase III (journeys), never Phase II (single decisions). |

| **D24** | **The Chrome/WebMCP lane is the next phase gate, and the lane changes but the measurement language does not.** Chrome must be *another lane populating `provider-conformance-report/1`* — not a reason to redesign the schema. Acceptance requires live registration/discovery/execution (read + state-changing) via real `document.modelContext` with `RegisteredTool` handles, preserved evidence, captured `browserVersion`, comparability-without-conflation vs. the reference lane, and **one intentionally browser-owned failure** proving `Browser Runtime: FAIL / Provider: PASS`. Explicitly not Phase III (no journeys). | If the schema must change to fit Chrome, the abstraction was incomplete; if Chrome slots in as a lane, that is the proof. Real models (done) + real WebMCP runtime (this) are the two independent dimensions that make Phase II genuinely real. See §14. |

## Ratified requirements folded in from review

- **Attribution categories:** `provider_definition`, `provider_runtime`, `browser_runtime`,
  `consumer_adapter`, `model_tool_selection`, `model_arguments`, `execution_bridge`,
  `provider_execution`, `evidence_contract` (§05).
- **Divergence classes:** behavioral / outcome / conformance (§07).
- **The target report sentence** ("Provider: PASS … Consumer execution bridge: FAIL, invalid
  RegisteredTool invocation") is the acceptance bar for the report's expressiveness (§05, §06).
